Come facciamo oggi

  1. Apri VS Code nella tua cartella Claude Workspace.
  2. Mostra lo screenshot della tabella di verifica (o rifalla adesso).

La verifica

Si incolla nel pannello di Claude, in VS Code:

Controlla che il mio computer sia pronto per il corso di Claude Code. Esegui tu i comandi che servono, senza installare né modificare nulla. Alla fine mostrami solo una tabella con tre colonne (Cosa, Versione o stato, OK?) per: Claude Code, Git, VS Code (se il comando code non risponde, controlla se l'app è installata: su Mac in /Applications, su Windows nella cartella Programs di AppData\Local), Homebrew se sono su Mac oppure Chocolatey se sono su Windows, Pandoc, GitHub CLI e login a GitHub, il file CLAUDE.md di questa cartella (OK solo se non contiene più parti tra [[ ]]), le skill messaggio-settimanale, riassunto-visita e nuovo-tool nella cartella .claude/skills. Sotto la tabella, per ogni riga che non è OK, scrivi in una frase cosa devo fare.

Dove ci si blocca di solito

Mac

  • command not found: claude: manca il PATH (due comandi nella guida)
  • command not found: brew: saltati i «Next steps» di Homebrew
  • VS Code non vede un programma appena installato: chiudi e riapri VS Code

Windows

  • 'claude' is not recognized: manca %USERPROFILE%\.local\bin nel PATH
  • 'irm' is not recognized: sei nel Prompt dei comandi, non in PowerShell
  • Chocolatey: PowerShell va aperta «come amministratore»

E adesso si lavora

  • Come si parla a Claude: il risultato e il contesto, non i passaggi.
  • Il tuo CLAUDE.md: cosa sa Claude di te e dei tuoi clienti.
  • Le skill: le cose che fai ogni settimana diventano un comando.
  • Primo tool: da un tuo Excel a una pagina da consultare dal telefono.
